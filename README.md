## `> cat philosophy.txt`

```
Architecture first. Code second.

Before writing a single line:
  1. Understand the real problem (not just the stated one)
  2. Design boundaries - what talks to what, and how
  3. Pick patterns that fit the domain, not the hype
  4. Build iteratively, ship incrementally
  5. Document decisions, not just behavior

On quality:
  - Static analysis at max level — PHP and TypeScript, zero tolerance
  - If it's not tested, it's broken - you just don't know yet
  - Copy-paste is a future bug with a delay timer
  - A codebase you can hand off is a codebase worth having

On AI:
  - It's a tool, not a shortcut to skip thinking
  - Use it to move faster, not to avoid understanding the problem
```
